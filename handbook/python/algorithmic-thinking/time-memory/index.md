## Чему научимся

Оценивать рост числа операций и объём крупнейшей структуры до запуска.

В первом KNN мы перебирали всех обучающих соседей для каждого запроса. На 12 строках это удобно; на миллионе уже важно оценить работу до запуска. Если обучающих объектов n, а признаков d, только расчёт расстояний для одного запроса требует пройти n·d координат. Сортировка соседей добавляет свою работу. Поэтому дальше отдельно рассматриваем число действий и объём хранимых данных.

## Размер входа и порядок роста

Пусть $n$ — число объектов. Суммирование списка делает примерно $n$ сложений. Для пар разных объектов без учёта порядка первый объект образует $n-1$ пар со следующими, второй — $n-2$, последний — ни одной. Всего $(n-1)+(n-2)+\cdots+1=n(n-1)/2$ проверок. При увеличении входа в 10 раз первая работа растёт примерно в 10 раз, вторая — примерно в 100.

Запись $O(n)$ означает верхнюю оценку роста с точностью до постоянного множителя при достаточно большом $n$. Это не секунды. $O(1)$ — постоянное число действий, $O(n^2)$ — квадратичный рост, $O(n\log n)$ обычно встречается у сортировки сравнением. Логарифм по основанию 2 отвечает на вопрос, сколько раз нужно удвоить 1, чтобы получить число: $\log_2 8=3$, потому что $2^3=8$. Для 1024 это 10. Поэтому «половинить диапазон до одного элемента» требует примерно $\log_2 n$ шагов. Основание логарифма не меняет такой класс роста. Здесь предполагаем, что сравнение или сложение небольших чисел занимает постоянное время.

Время зависит также от кода программы, компьютера и формата данных. Замер на одном маленьком входе не доказывает оценку роста для больших входов; такую оценку называют асимптотикой. Обозначение $O$ само по себе также не обещает точного времени: линейный алгоритм может иметь большую постоянную стоимость.

## Большие таблицы и память

Байт — единица объёма памяти. В следующих оценках GB означает миллиард байт; служебные данные самой структуры считаются отдельно. Плотная таблица хранит каждую ячейку, включая нулевые.

Числовая таблица из миллиона строк и 20 столбцов с 8 байтами на число занимает около 160 миллионов байт без служебных данных. Списки Python обычно требуют заметно больше. Копирование таблицы удваивает занятую ею память, а таблица всех попарных расстояний содержит уже $n^2$ чисел.

Если требуется только сумма, читайте строки последовательно и храните накопитель. Если требуются все пары расстояний, подумайте об обработке блоками. Не выделяйте огромный массив ради учебного замера: сначала оцените размер формулой.

## Разобранный пример: рост таблицы расстояний

Для n объектов таблица всех попарных расстояний имеет n строк и n столбцов. Если объектами являются 1 000 строк, нужно миллион чисел. При 10 000 строках — уже сто миллионов. Важно подставлять число объектов, а не число признаков.

```python
n = 1000
bytes_per_number = 8
matrix_bytes = n * n * bytes_per_number
assert matrix_bytes == 8_000_000
```

Подчёркивания в записи числа помогают читать разряды и не меняют значения. Дополнительная память — память для структур, которые алгоритм создаёт помимо исходных данных. Если читать по одному объекту и хранить только текущий минимум расстояния, полной таблицы не нужно. Однако число сравнений всё ещё может оставаться квадратичным.
