# Добавление, сборка и публикация материалов

Команды выполняются из корня репозитория. Сайт публикуется на [GitHub Pages](https://beloai.github.io/materials/).

## Что нужно для сборки

- Python 3, GNU Make и Bash 4 или новее.
- TeX Live с `pdflatex`, пакетами Beamer, TikZ, математическими пакетами и поддержкой русского языка.
- `pdfinfo` и `pdftoppm` из Poppler — для превью PDF.
- Jupyter и `nbconvert` — для HTML-версий ноутбуков. Без Jupyter доступно скачивание `.ipynb`.
- Node.js 22 и npm — для интерфейса Lit.

В CI зависимости устанавливаются автоматически. На macOS системного Bash 3 недостаточно: установите современный Bash и убедитесь, что он доступен через `PATH`. Шрифты уже находятся в `site/fonts/`; для их обновления служит `bash scripts/vendor-fonts.sh`.

После клонирования установите зависимости интерфейса:

```bash
npm --prefix site ci
```

## Добавить материал

1. Скопируйте шаблон нужного раздела: [лекции](../lectures/README.md), [практики](../practices/README.md) или [задания](../assignments/README.md).
2. Заполните `meta.yaml`: название, дату, описание, `build: true`. Для задания добавьте `assignment_type`.
3. Обновите `main.tex` и содержимое либо укажите готовый PDF в поле `pdf`. Порядок фрагментов задают команды `\input` в `main.tex`.
4. При необходимости добавьте файлы в `materials/` и ссылки в `references`.
5. Назначьте материал неделе в корневом `course.json`.
6. Соберите материал и сайт, проверьте результат в браузере.

Нумерация каждого раздела независима. Например, `lectures/02-topic` даёт подпись «Лекция 2». Папки `_template*` не публикуются.

Материал может содержать только ссылки или ноутбук: в таком случае `main.tex` не нужен. Сайт показывает запись, если есть хотя бы один собранный файл или внешняя ссылка.

## Метаданные: `meta.yaml`

Пример минимальной записи:

```yaml
title: "Название занятия"
date: "2026-10-10"
description: "Что изучим и какие задачи разберём."
build: true
```

| Поле | Назначение |
| --- | --- |
| `title` | Название материала |
| `subtitle` | Необязательный подзаголовок |
| `description` | Краткое описание для учеников |
| `date` | Дата занятия или выдачи задания, `YYYY-MM-DD` |
| `slot` | Время занятия: `1` — 11:25–12:50, `2` — 13:15–14:40; по умолчанию `1` |
| `time` | Произвольное время, например `10:30–12:00`; заменяет `slot` |
| `assignment_type` | Для заданий: `math` или `coding` |
| `build` | `false` отключает общую сборку и публикацию записи; по умолчанию `true` |
| `hidden` | `true` скрывает запись из каталога, сохраняя сборку файлов; по умолчанию `false` |
| `pdf` | Необязательный относительный путь к готовому основному PDF; имеет приоритет над `main.tex` |
| `lang` | Справочная отметка языка; язык LaTeX задаётся в `main.tex` |
| `materials` | Дополнительные файлы |
| `references` | Внешние ссылки |

Для задания время не подставляется автоматически: используйте `time`, если оно требуется. В общем каталоге новые даты идут первыми, задания первыми внутри даты, затем лекции и практики по времени от поздних к ранним. На странице недели материалы сгруппированы по виду и следуют порядку `course.json`.

Используется простой парсер, а не полный YAML: обычные поля и списки записей. Пишите описания одной строкой, без многострочных блоков и комментариев после значений.

### Готовый PDF вместо TeX

Для лекции, практики или задания создайте папку занятия и `meta.yaml`, положите PDF, например, в `materials/lecture.pdf`:

```yaml
title: "Название занятия"
date: "2026-10-10"
description: "Что изучим и разберём."
build: true
pdf: materials/lecture.pdf
```

Для домашнего задания также укажите `assignment_type: math` или `coding`. Выполните `make session DIR=lectures/02-topic`, затем `make site`. Файл станет основным PDF с превью первой страницы. В `materials` его повторно перечислять не нужно; другие PDF можно добавить туда как дополнительные файлы.

Путь должен быть относительным и оставаться внутри папки занятия, включая цель символической ссылки. Пробелы и кириллица допустимы. Файл проверяется утилитой `pdfinfo` из Poppler; отсутствующий, повреждённый или зашифрованный PDF вызывает ошибку без подмены TeX-версией. Имя `main.pdf` зарезервировано для результата TeX: используйте другое имя для исходного файла.

При наличии `pdf` обычная сборка не запускает TeX. Команда `make tex DIR=lectures/02-topic` отдельно создаёт локальный `main.pdf` и не заменяет опубликованный файл. Чтобы вернуться к TeX, удалите поле `pdf` и пересоберите занятие. Старые PDF, превью и дополнительные файлы удаляются при пересборке; общая сборка также удаляет результаты исключённых и удалённых занятий.

Исходные PDF коммитятся вместе с материалом. `make clean` сохраняет их, удаляя только результаты сборки и файлы LaTeX.

### Файлы

Пути задаются относительно папки материала:

```yaml
materials:
  - path: materials/notebook.ipynb
    label: Разбор задач
  - path: materials/data.csv
    label: Данные
```

`label` необязателен, но помогает различать несколько файлов. При совпадении подписей файлов к ним добавляются имена файлов. Сборка копирует файлы в `_site/materials/<раздел>/<папка>/`, без исходных вложенных папок. Поэтому имена файлов внутри одного материала должны различаться. Для `.ipynb` создаётся HTML без выполнения ячеек. Отсутствующие файлы пропускаются с предупреждением; ссылки на них не публикуются.

### Внешние ссылки

```yaml
references:
  - kind: contest
    url: https://new.contest.yandex.ru/contests/98758
    label: Задачи занятия
```

Замените URL на адрес своего контеста для учеников. Для `contest`, `kaggle`, `huggingface`, `colab` подписи по умолчанию — «Яндекс.Контест», «Kaggle», «Hugging Face», «Google Colab». Для произвольной ссылки укажите `label` и `url`. Используйте HTTP или HTTPS. Контесты показываются первыми, остальные ссылки — по подписи.

## Команды

```bash
make session DIR=lectures/02-topic  # PDF и дополнительные файлы одного занятия
make tex DIR=lectures/02-topic      # только локальная TeX-сборка, без публикации
make materials DIR=lectures/02-topic  # только дополнительные файлы
make handbook                     # учебник и общая оболочка, без сборки занятий
make frontend                     # только CSS и JS интерфейса
make test                         # тесты генератора и проверки манифеста
make site                         # все материалы, превью, интерфейс и манифест
make clean                        # удалить результаты сборки и файлы LaTeX
```

`make` равнозначен `make site`. Команда `make session` обновляет PDF, превью и дополнительные файлы, но не обновляет каталог: после неё выполните `make site`. Ошибки LaTeX смотрите в `main.log` папки материала. Сборка подключает общие пакеты через `TEXINPUTS` и дважды запускает `pdflatex`.

Для локального просмотра:

```bash
python3 -m http.server 8000 --directory _site
```

Откройте <http://localhost:8000/>. Нужен HTTP-сервер: открытие `index.html` через `file://` не подходит для загрузки манифеста.

Для материала с PDF создаётся PNG-превью первой страницы. Если PDF нет, для первого доступного ноутбука из списка `materials` создаётся SVG с первыми непустыми ячейками кода, подсветкой синтаксиса и значком Python. Ячейки не выполняются; их сохранённые выводы не отображаются. Превью ноутбуков работают для лекций, практик и заданий. Название материала открывает PDF, HTML-версию ноутбука или `.ipynb` в этом порядке. Превью появляется при наведении или фокусе на компьютере; на телефоне оно отключено. Ноутбук без кода или повреждённый ноутбук остаётся без превью; ошибки чтения выводятся как предупреждения.

## Структура занятий: `course.json`

Неделя — учебный модуль; даты занятий не определяют её номер. Порядок недель задаёт массив `weeks`, порядок материалов внутри каждого раздела — массив `materials` недели:

```json
{
  "title": "Подготовка к BelOAI",
  "description": "Краткое описание подготовки.",
  "weeks": [
    {
      "slug": "intro-ml",
      "number": 1,
      "title": "Введение в машинное обучение",
      "description": "Темы этой недели.",
      "materials": ["lectures/01-intro-ml", "practices/01-numpy-pandas"]
    }
  ]
}
```

`slug` состоит из строчных латинских букв, цифр и одиночных дефисов между ними; это постоянная часть URL `/weeks/<slug>/`. Номера — уникальные неотрицательные целые числа. Название и описание обязательны для раздела подготовки и каждой недели. Идентификатор материала — путь его папки от корня репозитория.

Все публичные материалы должны быть назначены ровно одной неделе, включая ещё не собранные. Неизвестные идентификаторы, повторы, одинаковые номера или slug останавливают генерацию. В ссылках структуры можно сохранять скрытые и отключённые материалы: в публикацию они не попадут. Недели без доступных ресурсов не выводятся; старые страницы недель удаляются при генерации.

Главная находится в корне сайта, общий каталог — `/materials/`. На GitHub Pages адреса учитывают префикс `/materials/` репозитория: например, общий каталог доступен по `/materials/materials/`. Файлы сохраняют прежние адреса.

## Как устроен сайт

`build-all.sh` вызывает `build-session.py`, который выбирает готовый PDF или TeX и публикует его. `build-materials.sh` копирует дополнительные файлы и запускает `material_preview.py`: тот создаёт превью первой страницы PDF либо кода первого доступного ноутбука. `generate-site.py` проверяет структуру занятий и публикует `materials.json`, статические страницы и шрифты; HTML формирует `course_site.py` по шаблону `site/index.html`. esbuild собирает интерфейс из `site/src/` в `_site/assets/`.

Манифест содержит `version: 2`, объект `course` и массив `materials`. Объект `course` повторяет структуру `course.json`, но содержит только опубликованные недели и доступные материалы. В записи находятся `id` (путь папки), `kind`, `number`, `title`, `subtitle`, `description`, `date`, `time`, списки `materials` и `references`. Для задания есть `assignment_type`; для доступных PDF и превью — `pdf` и `thumb`. Поле `thumb_href` задаёт переход по превью. Адреса файлов относительны корню сайта. Дополнительный файл содержит `label`, `download`, `open`, `is_notebook`; недоступный адрес обозначается пустой строкой. Внешняя ссылка содержит `kind`, `label`, `url`.

HTML содержит навигацию и все ресурсы без JavaScript. Lit загружает манифест для поиска и фильтров общего каталога; при ошибке загрузки статический список остаётся доступен. Поиск по названию, подзаголовку и описанию использует параметр `q`; фильтры поддерживают `#lectures`, `#practices`, `#assignments`. Старые hash-ссылки с главной переводят в каталог. Назад/вперёд восстанавливают поиск и фильтр. CSS и JS поставляются локально, без CDN.

## Проверка и публикация

Перед публикацией выполните `make test` и `make site`. Проверьте главную и страницы недель, прямое открытие URL, мобильное меню, работу без JavaScript, клавиатуру и превью. В каталоге проверьте поиск вместе с фильтрами, историю браузера, даты, ссылки, скачивание файлов и просмотр ноутбуков. Материалы без PDF не должны иметь ссылки на PDF; скрытые записи не должны попадать в каталог.

### Проверка в браузере

После `make site` запустите локальный HTTP-сервер, как описано выше. В другом терминале выполните:

```bash
mkdir -p output/playwright
npx --yes --package @playwright/cli playwright-cli -s=materials open http://localhost:8000/
npx --yes --package @playwright/cli playwright-cli -s=materials run-code --filename scripts/check-browser.js
```

Нужны Node.js и браузер, поддерживаемый Playwright CLI. Сценарий проверяет текущие две недели, пять материалов, страницу лицензии и соцсети: поиск, фильтры, переход к содержимому, историю, ошибку манифеста, превью с фокусом и наведением, работу без JavaScript. Он делает снимки главной, недель, каталога и лицензии на ширинах 360, 768, 991, 992 и 1440 px с открытым и закрытым меню в светлой и тёмной системной теме; проверяет цвета CS50 и переключение темы без перезагрузки. Результаты остаются в игнорируемом `output/playwright/`. Проверка короткого окна использует размер 1024×400.

Workflow `.github/workflows/presentations.yml` при изменениях материалов, `course.json` или сборки проверяет сайт. В pull request он сохраняет артефакт `_site/`; при push в `main` также публикует сайт на GitHub Pages. Изменения только корневой документации не запускают этот workflow.

Не коммитьте `_site/`, `main.pdf`, вспомогательные файлы LaTeX и `node_modules/`. Лицензии описаны в [LICENSING.md](../LICENSING.md).

## Черновик учебника

Учебник находится в разработке и доступен по прямому адресу `/handbook/`; главный README ссылается на черновик учебника по МЛ. Не добавляйте учебник в общее меню и каталог до отдельного решения о выпуске. Страницы и HTML-превью ноутбуков получают `noindex, nofollow`; это указание поисковым роботам, а не ограничение доступа. Успешные тесты не означают педагогической готовности материалов.

Авторские SVG по формулам и координатам примеров обновляются командой `python3 scripts/handbook_figures.py` (нужны NumPy и matplotlib). Для проверки без изменения исходных рисунков укажите `--output /tmp/handbook-figures`. После обновления проверьте подписи, точки и заштрихованные области на ширине 360 px.

`handbook/handbook.json` хранит каталог исходных уроков в `tracks[].chapters[].lessons`. Глава содержит `id`, `title`, `description` и список уроков. Урок имеет ID `<предмет>/<глава>/<урок>`, темы, результаты и зависимости от других уроков.

Состав самостоятельных учебников задаёт `handbooks`: `slug`, `title`, `description`, `introduction` (`<slug>/start`) и `sections`. Раздел содержит `slug`, `title`, `description`, `lessons` — список ID исходных уроков в порядке чтения. Один ID может входить в разные учебники, но не повторяться внутри одного. Каждый учебник включает все уроки своего предмета. Введения хранятся в `handbook/<slug>/start/index.md`.

«Назад» и «Далее» следуют порядку разделов и уроков текущего учебника, начиная с введения. Уроки `planned` пропускаются, `optional` образуют отдельные связанные ветки по исходным главам и зависимостям. Предварительные знания проверяются на существование, доступность и отсутствие циклов; они могут вести в другой учебник или вперёд по текущему маршруту. Единого смешанного маршрута больше нет.

`/handbook/` — выбор учебника. Собственные уроки сохраняют адрес `/handbook/<ID>/`; включённые из другого предмета получают контекстный адрес `/handbook/<slug>/<ID>/` (например, `/handbook/ml/python/numerical-data/numpy-arrays/`). Ссылки на включённые уроки сохраняют контекст; ссылки на остальные знания ведут к исходному адресу. Данные, ноутбуки и HTML-превью публикуются однократно по исходным адресам. Генератор пересчитывает относительные URL изображений и файлов. Не копируйте исходники ради включения в другой учебник.

Текст урока хранится в `handbook/<раздел>/<глава>/<урок>/index.md`. Для публикации нужны `status: "draft"` или `"reviewed"`, `build: true` и настоящая дата. Будущие уроки имеют `status: "planned"`, дополнительные — `optional: true`. Ресурсы задаются полями `path` и `label` относительно папки урока, внешние ссылки — `references` с `label` и `url`. При изменении программы обновляйте `handbook/PROGRAM.md`.

Начинайте текст с `## Чему научимся`, без заголовка первого уровня. Далее — объяснения, разобранные примеры, по две задачи трёх уровней с подсказками и решениями в `<details>`, итоги. Новые понятия объясняйте до использования. Пишите собственные тексты; заимствования сопровождайте источником и условиями использования. Формулы — `$…$` и `$$…$$`, исполняемые примеры — блоки `python`. Ссылки относительны опубликованной странице: из урока к общим данным — `../../../data/`. Происхождение данных описано в `handbook/data/README.md`.

После правки Markdown синхронизируйте ноутбуки командой `python3 scripts/handbook_notebooks.py --write`; `--check` проверяет синхронность. Решения в ноутбуках автоматически выносятся после задач. Самостоятельный ноутбук обязателен для каждого готового урока Python и ML; математика читается без ноутбуков. Авторские рисунки хранятся в `handbook/data/figures/` и публикуются вместе с общими данными. Запуск примеров не требует сети или GPU. В ноутбуках прежних страниц команда обновляет только ссылки на отдельные уроки; остальное содержимое сохраняется для совместимости.

Старые адреса описаны в `aliases`: `id`, `title`, новые `lessons`, старые `anchors` с полями `id`, `label`, `target` и прежние `resources`. Для них создаются страницы перехода с обычными ссылками; якорь ведёт к подходящему уроку и разделу. Не удаляйте эти записи и файлы прежних ресурсов. Служебные статусы и даты на ученических страницах не показываются.

`make handbook` собирает интерфейс и три учебника без LaTeX; `make site` собирает весь сайт. Требуются зависимости `npm --prefix site ci`. Markdown и формулы обрабатываются Node-рендерером; Python проверяет структуру, зависимости, пути, файлы и якоря. Jupyter/nbconvert создаёт HTML ноутбуков без выполнения. Общие данные и KaTeX публикуются локально вместе с лицензиями.

Для `make test` установите в виртуальную среду `handbook/start/requirements.txt` и `nbclient nbformat ipykernel nbconvert`. Проверки выполняют каждый доступный ноутбук в отдельном чистом ядре; ранние примеры дополнительно работают с `-I -S`. Результаты выполнения исходные ноутбуки не перезаписывают. В CI зависимости устанавливаются до тестов, PyTorch используется из CPU-индекса.

После сборки проверьте навигацию и каталог в браузере:

```bash
npx --yes --package @playwright/cli playwright-cli -s=handbook open http://localhost:8000/handbook/
npx --yes --package @playwright/cli playwright-cli -s=handbook run-code --filename scripts/check-handbook-browser.js
```

Сценарий проверяет дерево, активный урок, старые адреса, мобильную вёрстку, клавиатуру, работу без JavaScript и фильтры каталога. Он также работает под префиксом сайта. Снимки сохраняются в игнорируемом `output/playwright/`.
