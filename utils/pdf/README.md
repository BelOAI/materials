# PDF учебников

Стандартный профиль `reader`: Pandoc + pdfLaTeX, A4, одна колонка, 10 pt, компоновка olymp.sty. Основной текст и математика используют Computer Modern, русские глифы — T2A/LH, заголовки — Computer Modern Sans Serif, код — Computer Modern Typewriter. Подмена на Latin Modern отключена. Chromium преобразует SVG в векторные PDF с печатной светлой темой, CSS-переменными и узорами; подсказки и решения печатаются полностью. Короткие листинги сохраняются на одной странице. Логотип имеет ширину 34 мм, иллюстрации без заданной ширины сохраняют естественный размер и уменьшаются при нехватке места. Профиль одинаково обрабатывает графику при настройках Pandoc 2.x и 3.x, без повторного масштабирования. Высота иллюстраций ограничена 78% текстовой области с сохранением пропорций, чтобы подписи не пересекались с нижним колонтитулом. Исходные Markdown и структура учебников не меняются. SVG должны содержать необходимые стили и изображения внутри файла: внешние загрузки и скрипты при преобразовании отключены.

Отдельные рисунки и таблицы центрируются. Соседние курсивные подписи из Markdown оформляются по [общим правилам](../../handbooks/guidelines/visuals.md): рисунок — снизу, таблица — сверху, одинаковым уменьшенным курсивом. Формат `Рис. N. …` при выводе нормализуется; номера сохраняются из исходника и не зависят от состава PDF. Alt-текст не становится подписью. Таблицы могут продолжаться на следующей странице с повторением заголовков. Рисунок и его подпись образуют неделимый блок в обоих профилях; подпись таблицы остаётся вместе с заголовком и первыми строками. Сборка PDF и сайта отклоняет отдельные рисунки и таблицы без соседних подписей. Подписи добавляются в исходный Markdown и, при наличии, в Markdown-ячейки ноутбука; код и результаты ячеек сохраняются.

## Зависимости

Нужны Python 3.14, Pandoc, pdfLaTeX, XeLaTeX (для логотипа), Poppler (`pdfinfo`, `pdffonts`, `pdftoppm`) и пакеты из `requirements.txt` этой папки. TeX должен включать CM Super, поддержку русского языка, `fontspec`, `babel`, `standalone`, `titlesec`, `lastpage`, `adjustbox`, `float`, `caption`, `needspace`, `framed`, `fancyvrb` и математические пакеты.

```bash
python3 -m pip install -r utils/pdf/requirements.txt
python3 -m playwright install chromium --no-shell
# Debian / Ubuntu
sudo apt-get install pandoc lmodern texlive-xetex texlive-latex-extra texlive-lang-cyrillic \
  poppler-utils cm-super fontconfig fonts-liberation fonts-dejavu-core
# macOS: дополнительно установите MacTeX или соответствующий набор TeX Live
brew install pandoc poppler
# В TeX Live должен быть установлен cm-super.
```

На Linux системные зависимости Chromium можно установить командой `python3 -m playwright install-deps chromium`. После обновления Playwright повторите установку Chromium.

CI-образ включает PDF-инструменты и Chromium в `/opt/playwright`, доступный непривилегированному пользователю сборки. Команды `site` и `handbooks` PDF учебников не собирают; для них предназначен отдельный workflow `Handbook PDF`.

## Команды

Из корня репозитория:

```bash
make -f build/Makefile handbook-pdf                              # все учебники
make -f build/Makefile handbook-pdf DIR=handbooks/ml JOBS=2       # книга и её разделы
make -f build/Makefile handbook-pdf DIR=handbooks/ml/01-classic-ml
python3 utils/scripts/build-handbook-pdf.py handbooks/ml/01-classic-ml/01-first-experiment
python3 utils/scripts/build-handbook-pdf.py --all --output-dir output/pdf --jobs 2
python3 utils/scripts/build-handbook-pdf.py handbooks/ml --book-only --output output/pdf/ml-handbook.pdf
```

Путь к главе собирает главу и её параграфы; путь к книге — все три уровня. Результаты:

- `output/pdf/<book>/handbook.pdf`;
- `output/pdf/<book>/<chapter>/chapter.pdf`;
- `output/pdf/<book>/<chapter>/<paragraph>/paragraph.pdf`.

Имена берутся из `slug`, порядок книг — из `handbooks/handbooks.yml`, глав — из `chapters` в `handbooks/<книга>/meta.yml`, параграфов — из `paragraphs` в YAML глав. Структура каталогов и метаданных одинакова для сайта и PDF.

`--book-only` собирает только целые книги: с путём книги или `--all`. Существующие PDF глав и параграфов этот режим не удаляет. По умолчанию ссылки ведут на `https://materials.beloai.by/`.

`--output <файл.pdf>` задаёт путь при выборе ровно одного документа. `--output-dir` задаёт корень результатов поддерева; эти параметры несовместимы. Для ссылок на dev-версию задайте `--site-url https://materials.beloai.by/dev/`.

В состав главы входят её собственный `content.md`, если он есть, и доступные параграфы. В книгу дополнительно входит её вводный `content.md`. README, программа, данные и ноутбуки не вставляются в текст. Папки с `_`, `build: false` и `planned` пропускаются; `draft` с `build: true` включается. Пустые документы не создаются. Удалённые и исключённые материалы очищаются только внутри выбранного поддерева результатов.

Главы и книги — цельные документы с оглавлением, закладками и сквозной нумерацией страниц. Авторы указаны у соответствующих разделов. Ссылки на включённые разделы ведут внутрь PDF, остальные — на сайт. Изображения разрешаются относительно исходного текста и должны находиться внутри `handbooks/`, в том числе общие изображения и цели символических ссылок.

## Кэш и проверка

После сборки главы запустите `python utils/scripts/check-pdf-overlaps.py output/pdf/ml/classic-ml/chapter.pdf`. Проверка ищет наложение обычных слов, особенно в таблицах и диаграммах; формулы и итоговую компоновку дополнительно просматривайте глазами.

Общий проверяемый кэш `.cache/build/` хранит подготовленные деревья Pandoc, преобразованные SVG и готовые PDF раздельно. Неизменённый запуск восстанавливает результаты без Pandoc и TeX. Изменение параграфа пересобирает его PDF, родительскую главу и книгу. Одинаковые SVG преобразуются один раз независимо от пути; подготовка текста переиспользуется на всех уровнях. pdfLaTeX выполняется максимум в двух параллельных задачах по умолчанию.

Ключи учитывают содержимое, используемые ресурсы, порядок, профиль, код преобразования, бинарники инструментов, шрифты, формат TeX, реестр TeX Live при наличии и версию Chromium. Обновление движка SVG пересобирает рисунки и использующие их PDF. `BUILD_ENV_ID` позволяет явно обозначить смену окружения. `BUILD_CACHE_DIR` меняет расположение кэша; `BUILD_CACHE_DISABLE=1` отключает чтение и запись. Повреждённые записи пересобираются, неудачные результаты не кэшируются. Проверенные PDF заменяются атомарно; при ошибке прежний файл остаётся, а команда завершается с ненулевым кодом.

Команда выводит попадания в кэш, число компиляций, преобразований SVG и время. Для сравнения холодной и тёплой сборки выполните одну команду дважды. Удаление `output/pdf/` не требует повторной компиляции при сохранном кэше.

Синтетическая проверка настоящего SVG-рендеринга (CSS-переменные, печатная палитра, сетка, текст и векторный выход): `PDF_RENDER_TESTS=1 python3 -m unittest discover -s utils/scripts/tests -p test_handbook_svg.py`. Обычные тесты не требуют установки браузера и пропускают эти две проверки.

Интеграционная проверка книжного оформления, шрифтов, навигации, векторного логотипа и кэша: `PDF_RENDER_TESTS=1 python3 -m unittest discover -s utils/scripts/tests -p test_handbook_pdf_render.py`. Используются только синтетические учебники.

Перед передачей отрендерите PDF через `pdftoppm -png <файл.pdf> <префикс>` и просмотрите каждую страницу: формулы, глифы, рисунки, код и разрывы. Объём определяется учебной целью; правила изложения — в `handbooks/guidelines/content.md`. Результаты и кэш не коммитятся.

Общее оформление подключается через `\usepackage{academichandbook}` из `utils/latex/tex/latex/`. Основа — закреплённая копия [olymp.sty](../latex/tex/latex/olymp/README.md); интеграция Pandoc и фильтр коротких листингов находятся в этой папке.

На каждой странице — логотип BelOAI.team и контекст чтения: глава и текущий материал, а в выдержках — название документа и его раздел. Нижний колонтитул содержит «Страница N из M».

Полная книга начинается с титула: название, редакция исходников (release-тег при наличии и Git commit), дата commit, адрес сайта и лицензия. Локальные изменения отмечаются явно. Титул сохраняет шапку, но не содержит нижнего колонтитула; физически он остаётся первой страницей, поэтому следующая имеет номер 2. Для исходников без Git выводится «Локальная редакция (без Git)».

Список участников берётся из `contributors` в `handbooks/<книга>/meta.yml`; поле `github` задаёт активную ссылку на профиль. Маркер `<!-- handbook-contributors -->` во вводном `content.md` вставляет список в указанное место и на сайте, и в PDF; отдельная страница участников тогда не создаётся. Без маркера список печатается перед оглавлением. В ML-учебнике список включён в подраздел «От кого?» раздела «От авторов». Изменения списка и редакции пересобирают только полные книги. Выдержки сохраняют компактное начало без версии и отдельного списка участников. Главы полной книги начинаются с новой страницы. Логотип — векторный: Unbounded Bold для BelOAI и IBM Plex Sans Regular для .team. FontTools создаёт статические TTF из локальных WOFF2 сайта, затем XeLaTeX собирает эмблему один раз; результат кэшируется отдельно. Системная установка фирменных шрифтов не нужна. Шрифты сохраняют собственные лицензии OFL.

Ключ PDF учитывает оба общих пакета, интеграцию Pandoc и содержимое логотипа; ключ логотипа — его исходник, шрифты, FontTools и окружение TeX. Изменение оформления сохраняет кэши подготовленного текста и SVG. Общие печатные Unicode-символы поддерживаются в LaTeX-адаптере; исходный Markdown не переписывается.

## Автоматические выпуски

`Handbook PDF` запускается на каждый push в `main`, теги `v*` и вручную. Проверяет источник, запускает синтетические Python-тесты и собирает только ML-книгу. Артефакт на 90 дней содержит `beloai-ml-handbook.pdf`, `beloai-ml-handbook-belarus-textbook.pdf` и `SHA256SUMS`; `pdfinfo` проверяет наличие страниц. Кэш использует хеш окружения, включая PDF-зависимости. Задача сборки имеет `contents: read`, задача публикации — `contents: write`; publisher берёт скрипт из `main` и артефакт своего run, без дополнительных секретов.

Последняя успешная сборка актуальной вершины `main` обновляет prerelease и тег `main-preview`. SHA и ссылка на сборку находятся в описании. Устаревший запуск пропускается; prerelease не становится Latest. После ошибки загрузки можно повторить workflow: незавершённый draft будет дополнен.

Для стабильного выпуска создайте тег на commit из истории `main`: первый выпуск дня — `v2026.10.25`, следующие — `v2026.10.25.1`, `.2` и далее. Дата должна существовать, ревизия — положительная без ведущих нулей. Пример:

```bash
git tag v2026.10.25 <commit-из-main>
git push origin v2026.10.25
```

Сборка использует именно commit тега. Release публикуется после загрузки обоих PDF и `SHA256SUMS` в draft; повторный запуск завершает draft, но не заменяет assets опубликованного стабильного выпуска. Исправления выпускаются новым тегом. Latest получает максимальная дата и ревизия, поэтому исторический тег не вытесняет новый выпуск. Общая очередь `handbook-releases` с [`queue: max`](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) последовательно обрабатывает до 100 ожидающих запусков без замены предыдущего ожидающего тега.

После внесения workflows в `main` проверьте prerelease. Первый стабильный release создавайте только настоящим release-тегом, без тестовых выпусков в публичной истории.

## Издательский макет для Беларуси

Профиль `reader` остаётся стандартным. Альтернативный `belarus-textbook` использует
те же Markdown, порядок разделов, подписи авторов, рисунки и решения. Он предназначен
для редакционной работы над полной книгой для читателей 15–18 лет. Поддерживаются
только полные книги; прямой вызов Python требует `--book-only`.

```bash
make -f build/Makefile handbook-pdf DIR=handbooks/ml PROFILE=belarus-textbook
python3 utils/scripts/build-handbook-pdf.py handbooks/ml --book-only --profile belarus-textbook
python3 utils/scripts/build-handbook-pdf.py handbooks/ml --book-only --profile belarus-textbook \
  --output output/pdf/beloai-ml-handbook-belarus-textbook.pdf
```

По умолчанию новый профиль пишет `output/pdf/belarus-textbook/<book>/handbook.pdf`.
Пути `reader` сохраняются. `--output-dir` заменяет корень результатов выбранного
профиля: для двух профилей задавайте разные каталоги. Общая очистка стандартного
каталога `reader` пропускает подкаталог `belarus-textbook`. Выбор профиля и его стиль
входят в ключ PDF, подготовленный текст и SVG переиспользуются. Изменение
`publication.yml` меняет только издательский макет, изменение общего
`handbookcommon.sty` — оба профиля.

Оформление подключается через `\usepackage{belarustextbook}` и не использует
`olymp.sty`: 170 × 240 мм, одна колонка, Computer Modern / CM Super, 13/16 TeX pt,
зеркальные поля: базовое внутреннее 20 мм плюс `bindingoffset=5mm` (gutter),
то есть 25 мм от края страницы до полосы у корешка, 15 мм снаружи, 20 мм сверху,
22 мм снизу. Gutter прибавляется один раз; ширина полосы — 130 мм. Колонтитулы
компактные, титульный лист и его оборот без видимого номера; физическая нумерация
сквозная. Главы начинаются с новой страницы. Короткие листинги сохраняются вместе,
длинные могут продолжаться на следующей странице; длинные строки кода переносятся
без уменьшения всего блока. Длинные идентификаторы в тексте и адреса ссылок
получают точки переноса (идентификаторы — по разделителям, CamelCase и не реже
чем через восемь знаков); группы отдельных формул, разделённых `\qquad`,
располагаются вертикально. Длинные цепочки с несколькими верхнеуровневыми
равенствами переносятся по знаку равенства; формулы с явными окружениями или
парными `\left`/`\right` сохраняют авторскую компоновку. Таблицы получают ширины колонок по содержимому
с переносом текста и повторяемыми заголовками. Нулевой пробел в начале
табличного абзаца разрешает TeX переносить также первое слово ячейки.
В длинных латинских названиях добавляются невидимые точки переноса с учётом
числа колонок: русская переносная таблица TeX не разбивает такие слова. Профиль `reader` сохраняет
прежнее поведение длинных строк кода.

Абзацный отступ — 5 мм, межабзацный интервал — 0; красная строка сохраняется и после заголовков, списков и блоков кода.
Pandoc получает `indent:true`, поэтому не подключает конфликтующий `parskip`.
Для списков используется `enumitem`: отступ есть только на первой строке пункта
(`leftmargin=0pt`, `itemindent=13mm`). Левый край номера или маркера совпадает
с красной строкой обычного абзаца: `labelindent=5mm`, `align=left`; ширина
места под номер — 6 мм, промежуток до текста — 2 мм.
Перенесённые строки и последующие абзацы пункта начинаются от левого края
полосы, без общего сдвига списка. То же правило действует для вложенных списков. Переключения кегля в листингах не сбрасывают настройки списков. Висячие строки подавляются. Заголовки полужирные прямые, выключены
влево: главы 22/26 pt, параграфы 16/20 pt, следующий уровень 14/18 pt, глубокие
уровни 13/16 pt. Интервалы перед/после: 24/16, 15/7 и 12/6 pt соответственно;
для глубоких уровней также 12/6 pt. Общий адаптер оставляет перед заголовком
место минимум для него и двух строк текста. Подписи и колонтитулы — прямые
11/14 pt; исходные номера и тексты подписей сохраняются. Код, таблицы и длинные
примечания используют основной кегль 13/16 pt, без масштабирования. Возврат через
`\normalsize` также устанавливает 13/16 pt. Эти параметры действуют только
в `belarus-textbook`. Дополнительно к общим TeX-зависимостям нужны
`geometry`, `fancyhdr`, `fix-cm`, `type1ec`, `indentfirst`, `enumitem` и `fvextra` (`type1ec` входит в CM Super,
остальные пакеты — в базовый TeX и `texlive-latex-extra`).
Пакеты `fix-cm` и `type1ec` включают произвольные размеры Computer Modern;
T2A-семейства перечитываются после подключения Pandoc, чтобы 13 pt не подменялись
дискретным размером 12 pt.

### Метаданные

Выходные сведения хранятся в `handbooks/<book>/publication.yml` и читаются только
новым PDF-профилем. Они не меняют каталог сайта. Обязательные строки: `kind`,
`status` (пока только `Издательский макет`), `audience`, `annotation`, `edition`.
Объект `classification` содержит `udk`, `bbk`, `author_mark`, каждый с полями:

```yaml
value: '004.8'
status: preliminary  # либо verified после проверки библиографом
rationale: Основание выбора индекса и ограничения проверки.
sources:
  - https://udcsummary.info/php/index.php?id=13359&lang=en
```

Если хотя бы один индекс предварительный, на обороте титула печатается сообщение
о необходимости проверки библиографом. `value` — строка, в том числе для УДК и ББК.
Текст всех реквизитов передаётся Pandoc как текст, а не как команды LaTeX.

Необязательные поля `publisher`, `place`, `year`, `isbn`, `reviewers`, `approval`,
`production` имеют одинаковый вид: `{value: '...', source: 'документ или источник подтверждения'}`.
Пустые подтверждения отклоняются; сама запись `source` не заменяет редакционную
проверку подлинности. Год задаётся четырёхзначной строкой, ISBN-13 проверяется по
контрольной цифре. Отсутствующие реквизиты не печатаются и не подставляются
автоматически. Год издания не выводится из даты Git. Неизвестные и повторные ключи
отклоняются до подготовки ресурсов и очистки результатов.

Заглавие берётся из каталога учебников и используется без повторов на титуле,
обороте, заключительной странице и в метаданных PDF. На чётных страницах оно
заменяет `BelOAI` в колонтитуле; на нечётных сохраняется название главы. Номер
страницы остаётся у внешнего края, колонтитулы набраны 11/14 pt.

Титул формируется отдельными блоками Pandoc: существующий логотип шириной 24 мм,
заглавие 22/26 pt полужирным, вид материалов, читательский адрес и статус.
Подтверждённые место издания, издатель и год располагаются внизу титула.
Отсутствующие реквизиты не заменяются названиями проекта или годом исходников.
Название не объединяется с подзаголовком в `\@title`; `\maketitle` только
сохраняет экранированное Pandoc заглавие для колонтитулов.

Оборот содержит компактный блок классификации, предупреждение о предварительных
индексах, описание издания, аннотацию, редакцию и подтверждённые сведения
о рецензировании, утверждении и ISBN. Внизу расположены авторские права,
лицензия и указание, где перечислены авторы разделов. Титул и оборот не имеют
красных строк, колонтитулов и видимых номеров; физическая нумерация сквозная.
Оглавление остаётся самостоятельным разделом после выходных сведений
(и отдельного списка участников, если он предусмотрен метаданными книги).

Участники и авторы разделов берутся из существующих метаданных с сохранением ролей.
Заключительная страница разбита на сведения об издании, подтверждённые выпускные
данные и технические сведения: редакция Git, дата исходников, ссылки и формат.
Бегущий заголовок на ней отключён, номер страницы сохранён внизу.
Лицензия учебных материалов — CC BY 4.0; официальные тексты лицензий не изменяются.

Композиция этих страниц — издательское решение для макета. Основной стандарт
для состава и расположения выходных сведений — СТБ 7.4-2017. Его действующий
статус и область применения подтверждены официальным каталогом ТНПА; полный
текст повторно получить не удалось. Соответствие непроверенным пунктам
стандарта не заявляется. Это ограничение сохраняется до сверки полного текста.

- ББК `32.813`: ориентир по [каталогизации РГБ издания об искусственном интеллекте](https://search.rsl.ru/ru/record/01001269670), без неподтверждённого типового деления для школьников.
- Авторский знак `У91`: предварительно по первому слову «Учебник»; [пример коллективного учебника в каталоге РГБ](https://search.rsl.ru/ru/record/01003348340). Метод определения по двузначным таблицам Хавкиной описан [РГБ](https://www.rsl.ru/izdatelyam/udk-bbk-predmetnye-rubriki/). Это аналогия, а не официальное присвоение нашей книге.

аудитории или вида издания требует повторной библиографической проверки.

### Выпуски двух вариантов

CI собирает из одного commit `beloai-ml-handbook.pdf` и
`beloai-ml-handbook-belarus-textbook.pdf`. `SHA256SUMS` содержит две строки в этом
порядке. Отсутствие или повреждение любого файла останавливает публикацию; выпуск
становится публичным только после загрузки полного комплекта. Новая схема действует
для будущих стабильных выпусков и `main-preview`; опубликованные стабильные файлы
не заменяются. Перед включением workflow оба профиля нужно проверить локально.

## Печатный мастер внутреннего блока

Команда `--press-ready` допустима только с `--profile belarus-textbook --book-only`:

```bash
python3 utils/scripts/build-handbook-pdf.py handbooks/ml --book-only --profile belarus-textbook --press-ready
make -f build/Makefile handbook-pdf DIR=handbooks/ml PROFILE=belarus-textbook PRESS_READY=1
```

Результат — отдельный пакет `output/press/ml/`: `beloai-ml-handbook-press.pdf`,
`preflight.json`, `preflight.md`, `SHA256SUMS`. `--output-dir` меняет корень пакетов;
`--output` задаёт имя единственного мастера, отчёты размещаются рядом с ним.
Не направляйте печатный пакет в каталог двух публичных PDF. Проверенный мастер
заменяется только после успешной проверки; при ошибке предыдущий PDF сохраняется,
диагностика остаётся в `.cache/press-failures/`. Контрольные суммы охватывают PDF
и оба отчёта. Промежуточный RGB-макет использует обычный кэш `belarus-textbook`;
печатное цветопреобразование выполняется отдельно и не заменяет файлы `reader`.

Оформление печатного профиля: чёрный основной текст и код, цветные иллюстрации,
главы 22/26 pt, остальные уровни 16/20, 14/18 и 13/16 pt. Основной текст 13/16,
подписи и колонтитулы 11/14, поля и согласованные отступы абзацев и списков
сохранены. Главы начинаются на нечётной странице без бегущего заголовка;
намеренные пустые страницы не имеют номера и колонтитулов. При подготовке
мастера нечётный общий объём дополняется одной пустой страницей для двусторонней
печати. Основной макет сохраняет навигацию; из мастера удаляются аннотации ссылок,
действия и формы, при этом напечатанный текст ссылок остаётся.

Ширины таблиц вычисляются по содержимому: числовые колонки компактнее описательных.
Явные точечные настройки находятся в `utils/pdf/print-layout.yml`, вне учебных
материалов. Ключ — ID материала и `/table:N` либо `/figure:N`, N начинается с 1
в каждом материале. Допустимы `widths` (положительные доли с суммой 1, только для
таблиц), `break_before` (boolean), `space_before_pt` (число от 0 до 72).
Строки, значения, подписи и порядок объектов не меняются. Длинные таблицы
сохраняют повторяемые заголовки; вопросы с вариантами ответа группируются без
фиксированного запаса в половину страницы. Размер растров ограничивается
300 ppi без увеличения исходного числа пикселей. SVG-штриховки разворачиваются
во временном DOM в обрезанные векторные плитки: исходные SVG не переписываются,
обычный рендеринг `reader` не меняется.

### Принятые производственные условия

- PDF 1.6, отдельные страницы 170 × 240 мм, MediaBox = TrimBox = BleedBox.
- Цветная печать на немелованной бумаге. CMYK/Gray, чёрный основной текст —
  только чёрная краска. Нет вылетов, меток реза, обложки, корешка и спуска полос.
- Выходной профиль **PSO Uncoated v3 / FOGRA52** — принятое условие, а не
  подтверждённая спецификация типографии. [Официальная карточка ICC](https://registry.color.org/profile-registry/PSOuncoated_v3_FOGRA52)
  указывает немелованную бумагу и условия ISO 12647-2:2013, PS 5.
- Профиль загружается из официального реестра один раз в `.cache/press-profiles/`.
  SHA256: `7c39f74fbede1e8c85f8fbb9df7d359aea638b9b68dd0854fdd3ba386e3a02c0`.
  Изменение байтов блокирует сборку. Отдельный ICC-файл не включается в Git,
  Docker-образ или публикуемый пакет: условия разрешают встраивание и обмен
  встроенным профилем, но ограничивают распространение самого профиля.
  Исходные условия и источник включены в оба отчёта.

Нужны Ghostscript (`gs`), pypdf и Pillow из зависимостей PDF. Ghostscript
преобразует цвета без уменьшения разрешения растров; разрешение на чтение
ICC ограничено конкретным файлом при включённом SAFER. После преобразования
встраивается профиль, проверяются страницы, шрифты, цвет, разрешение, отсутствие
аннотаций и совпадение извлечённого текста. При сравнении текста игнорируются
пробелы и раскрываются только типографские латинские лигатуры; математические
символы не нормализуются. Перед сборкой фиксируются SHA256 всех файлов
`handbooks/`, после сборки требуется их полное совпадение.

Это техническая проверка под описанные условия, **не сертификат PDF/X**.
Само наличие OutputIntent не подтверждает PDF/X-соответствие;
[PDF Association](https://pdfa.org/technical-side-and-requirements-of-pdfx/)
описывает дополнительные ограничения. Не добавляйте идентификатор PDF/X
без полноценной проверки соответствия. Статус «Издательский макет»,
предварительная классификация и ограничения нормативной сверки сохраняются.

Синтетические проверки: `test_handbook_layout.py`, `test_handbook_press.py`;
реальная конверсия включается через `PRESS_RENDER_TESTS=1`, TeX/SVG — через
`PDF_RENDER_TESTS=1`. CI выполняет эти проверки и сохраняет печатный пакет
отдельным artifact `handbook-press-*`. Состав опубликованных выпусков остаётся
прежним: два PDF и их контрольные суммы; стабильные выпуски не перезаписываются.
Перед передачей обязательны рендеринг и просмотр каждой страницы макета и мастера.

## Самопроверка и вставки

Общий разборщик `handbook_blocks.py` проверяет явную структуру Markdown до
преобразования для сайта, PDF и ноутбуков. Формат исходника и пример:
[правила авторов](../../handbooks/guidelines/content.md#самопроверка-исходник-и-публикация).
Самопроверка не распознаётся по тексту заголовка или номеру вопроса.

Оба PDF-профиля оставляют вопросы в материале, а подсказки и решения собирают в
конце каждой главы полной книги или отдельной главы; PDF параграфа помещает их
в конец параграфа. Вопросы не засоряют оглавление. Ссылки на подсказку и решение
содержат физические номера страниц, которые остаются в print master после
удаления аннотаций. Разбор содержит обратную ссылку. Длинные вопросы могут
переноситься; коротким резервируется место вместе с вариантами.

Смысловые вставки используют общий чёрный разрывной контейнер `tcolorbox` с
векторными иконками, соответствующими локальным SVG сайта. Рамка не уменьшает
кегль текста. Обычные цитаты и раскрываемые инструкции не преобразуются во
вставки или тесты. Зависимости кэша включают разборщик, адаптеры и стили.
