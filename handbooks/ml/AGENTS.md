# Предпочтения для ML-учебника

Эти договорённости относятся к `handbooks/ml/`. Перед работой прочитайте [общие инструкции учебников](../AGENTS.md) и [guidelines](../guidelines/content.md).

## Текст и объяснения

- Пишите доброжелательно и понятно для школьников 10–11 классов, без сюсюканья. Текст должен помогать разобраться и попробовать самому.
- Объясняйте предмет прямо. Убирайте дежурные оговорки, защитные абзацы и повторяющиеся предупреждения. Не добавляйте в основной текст фразы вроде «все персонажи и числа придуманы» или «это учебный выбор, а не доказательство». Происхождение учебных данных фиксируйте в README занятия.
- Разбирайте вычисления подробно: исходные значения, подстановка, промежуточные действия, результат и его смысл. Например, расстояние до конкретного героя нужно посчитать по каждому признаку, затем сложить слагаемые.
- За формулой должно стоять объяснение: что означают величины, зачем выполняется преобразование и как оно работает на числовом примере. Не заменяйте объяснение общими словами о методе.

## Авторство и изображения

- В новых занятиях, которые готовим с пользователем, указывайте автора **Чернуха Алексей**. Авторство на странице и в ноутбуке должно совпадать с `authors` в метаданных.
- Добавляйте красивые уместные иллюстрации и содержательные схемы. Расстояния, шкалы и шаги алгоритма показывайте на точных диаграммах с читаемыми подписями; иллюстрации персонажей могут дополнять их.
- Ориентируйтесь на тёмный фон страницы. У инфографики должны согласованно меняться фон, панели, подписи, линии и акцентные цвета; проверяйте результат в тёмной теме. Сохраняйте читаемую светлую версию для светлой темы и печати.
- Для иллюстраций персонажей предпочтителен настоящий прозрачный фон PNG, чтобы изображение свободно вписывалось в страницу без светлой прямоугольной подложки. Небольшую полупрозрачную ауру вокруг персонажей можно сохранять.

## Порядок работы

- Для работы над учебником используйте ветку в репозитории без `codex` в имени; подходящий формат — `handbook/<тема>`.
- Сначала подготовьте и проверьте занятие локально, затем откройте пользователю почитать. PR в `dev` создавайте только после явного одобрения пользователем всех изменений.
- По завершении работы пользователь хочет вернуться на ветку `dev`. Перед переключением сохраните изменения в тематической ветке, чтобы работа не потерялась и не переехала на `dev` незакоммиченными правками.
