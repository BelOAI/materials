## Как работает K-means

Мы выбираем обычный вариант K-means с квадратом евклидова расстояния. **Центр группы** здесь — её центр масс, если считать все точки одинаково «тяжёлыми»: среднее арифметическое по каждой координате отдельно. Для группы из $m$ точек $(x_i;y_i)$ это

$$c=\left(\frac{x_1+\ldots+x_m}{m};\frac{y_1+\ldots+y_m}{m}\right).$$

Такой центр может находиться между точками и не совпадать ни с одной из них. K-means повторяет два действия:

1. **Распределение:** каждый объект относим к ближайшему центру.
2. **Обновление:** для каждой группы считаем новый центр как среднее её точек.

Для двух точек $(x,y)$ и $(a,b)$ сравниваем квадраты евклидовых расстояний: $d_2^2=(x-a)^2+(y-b)^2$. Само евклидово расстояние $d_2$ содержит квадратный корень. При выборе ближайшего центра корень можно не считать: он не меняет порядок расстояний. Если расстояния равны, нужно заранее договориться, какой центр выбрать; в основном примере равенств нет.

## Как измерить компактность

Для полученных групп K-means складывает **квадраты расстояний от точек до своих центров**. Обозначим сумму $J$:

$$J=\sum_{i=1}^{n} d_2^2(x_i,c_{g(i)}),$$

где $g(i)$ — группа точки $i$. После первого обновления $J=430{,}5$, после четвёртого — $90{,}33$; пятый раунд сохраняет это число. Для итоговой группы A–L сумма квадратов равна $\sum(x_i-22/12)^2+(y_i-40/12)^2=30{,}33$, для M–V — 60, вместе $90{,}33$. Среднее — подходящий центр именно для этой суммы: если $\bar x$ — средняя координата $x$ в группе, то $\sum_i(x_i-a)^2=\sum_i(x_i-\bar x)^2+m(a-\bar x)^2$. Последнее слагаемое наименьшее при $a=\bar x$; для $y$ рассуждение такое же. Поэтому оба действия K-means не увеличивают $J$: распределение выбирает ближайший центр, а пересчёт — лучший центр для полученной группы. Сравнивать $J$ между запусками осмысленно на **тех же точках, при том же $K$ и масштабе координат**. Меньшее $J$ означает более компактное разбиение по выбранному расстоянию, а не «правильный» смысл групп. Если изменить единицу одной координаты, расстояния и итог могут измениться.

## Проверим шаги на Python

Код повторяет пять раундов из таблицы 2. В каждой паре координат сначала $x$, затем $y$. Он останавливается, когда распределение не меняется; на наших данных это одновременно означает, что не меняются и средние. Для других данных отдельно понадобится обработка пустой группы и ограничение числа раундов.

```python
points = [(1, 1), (2, 1), (1, 2), (2, 2), (2, 3), (3, 3),
          (1, 4), (2, 4), (3, 4), (1, 5), (2, 5), (2, 6),
          (7, 6), (9, 6), (11, 6), (13, 6), (8, 7),
          (10, 7), (12, 7), (14, 7), (9, 8), (13, 8)]

def distance_squared(point, center):
    return sum((value - origin) ** 2 for value, origin in zip(point, center))

def run_kmeans(points, centers, max_rounds=20):
    previous_labels = None
    for number in range(1, max_rounds + 1):
        labels = [min(range(2), key=lambda j: distance_squared(point, centers[j]))
                  for point in points]
        groups = [[point for point, label in zip(points, labels) if label == j]
                  for j in range(2)]
        if any(not group for group in groups):
            raise ValueError("Пустая группа: выберите другие начальные центры")
        new_centers = [tuple(sum(point[j] for point in group) / len(group)
                             for j in range(2)) for group in groups]
        moved = (None if previous_labels is None else
                 sum(a != b for a, b in zip(labels, previous_labels)))
        print(number, "размеры:", [len(group) for group in groups],
              "сменили группу:", moved,
              "центры:", [tuple(round(value, 2) for value in center) for center in new_centers])
        if labels == previous_labels:
            return number, groups, new_centers
        centers, previous_labels = new_centers, labels
    raise RuntimeError("Достигнут предел раундов")

rounds, groups, centers = run_kmeans(points, [(13, 6), (14, 7)])
assert rounds == 5
assert groups == [points[:12], points[12:]]
print("Итоговые центры:", centers)
```

Первая строка вывода содержит размеры `20` и `2`, затем `15` и `7`, `13` и `9`, `12` и `10`, ещё раз `12` и `10`. Число сменивших группу пунктов равно соответственно `5`, `2`, `1`, `0` после первого раунда. `None` в первой строке означает, что предшествующего распределения для сравнения ещё не было. Для пустой группы нельзя вычислить среднее; в рабочей реализации заранее выбирают способ обработки такой ситуации.

Сверим итог с библиотекой. `tol=0` отключает досрочную остановку по малому сдвигу центров; `n_init=1` оставляет именно заданный нами старт, а не выбирает лучший из нескольких.

```python
from sklearn.cluster import KMeans

model_clouds = KMeans(n_clusters=2, init=[[13, 6], [14, 7]],
                      n_init=1, tol=0, algorithm="lloyd")
model_clouds.fit(points)
print("Раундов:", model_clouds.n_iter_)
print("Сумма квадратов:", round(model_clouds.inertia_, 2))
assert model_clouds.n_iter_ == 5
```

Получаем 5 раундов и $J\approx90{,}33$. Для другого старта A и V можно запустить ту же функцию или библиотечную модель: там потребуется только два раунда, но результат на этих точках будет тем же.

Для всех ирисов те же действия удобно выполнить библиотекой. `petals` содержит только две колонки измерений; известные виды `iris.target` в `fit_predict` не передаются. Начальные центры выбраны явно, поэтому результат повторяется:

```python
from sklearn.datasets import load_iris

iris = load_iris()
petals = iris.data[:, 2:4]
model = KMeans(n_clusters=3, init=petals[[0, 50, 100]], n_init=1)
groups = model.fit_predict(petals)
print(model.cluster_centers_.round(2))
```

Для работы с таблицами удобно дать двум размерам имена столбцов и добавить найденную группу. `pandas` позволяет затем посмотреть средние размеры внутри каждой группы; названия видов мы по-прежнему **не** передаём модели:

```python
import pandas as pd

flowers = pd.DataFrame(petals, columns=["length_cm", "width_cm"])
flowers["cluster"] = groups
print(flowers.groupby("cluster")[["length_cm", "width_cm"]].mean().round(2))
```

Число группы условно. Таблица средних помогает описать найденные группы, но не доказывает, что они совпали с ботаническими видами. В ноутбуке можно изменить начальные центры и увидеть, как меняются группы и их положение на диаграмме.

## Что изменится при другом расстоянии

Близость точек можно определить по-разному. Для точки $(x;y)$ и центра $(a;b)$ рассмотрим три расстояния:

*Таблица 3 — Три способа измерять расстояние*

| Название | Формула |
| :--- | :--- |
| Евклидово $L_2$ | $\sqrt{(x-a)^2+(y-b)^2}$ |
| Манхэттенское $L_1$ | $\lvert x-a\rvert+\lvert y-b\rvert$ |
| Максимум по координатам $L_\infty$ | $\max(\lvert x-a\rvert,\lvert y-b\rvert)$ |

Если группа уже известна и мы хотим уменьшить **сумму расстояний** до её центра, правило обновления зависит от выбранной строки таблицы. Для $L_2$ лучший центр называют *геометрической медианой*; в общем случае это не среднее. Для $L_1$ берём медиану координат $x$ и отдельно медиану координат $y$. При чётном числе точек можно выбрать любое значение между двумя центральными значениями отсортированных координат. Для $L_\infty$ обе координаты приходится подбирать совместно; простое покоординатное среднее в общем случае не даёт минимум суммы.

Не путайте расстояние $L_2$ с его **квадратом** из нашего K-means. При выборе ближайшего из уже заданных центров корень ничего не меняет: $4<9$ и $\sqrt4<\sqrt9$. Поэтому если оставить обновление центров средним, замена $d_2^2$ на $L_2$ даст **точно те же группы, центры и число раундов**. Но если цель — уменьшать *сумму самих расстояний* $L_2$, среднее уже не обязано быть лучшим центром.

Посмотрим на три точки $(0;0)$, $(0;0)$ и $(9;9)$. Их среднее — $(3;3)$. Сумма квадратов $L_2$ при этом центре равна $108$, а при $(0;0)$ — $162$: для обычного K-means среднее лучше. Если же складывать расстояния без квадратов, получится наоборот: для $L_2$ суммы равны $12\sqrt2$ и $9\sqrt2$, для $L_1$ — $24$ и $18$, для $L_\infty$ — $12$ и $9$ соответственно. Среднее не даёт минимум ни одной из этих трёх сумм.

**Опыт на наших 22 точках.** Оставим начальные центры $(13;6)$ и $(14;7)$ и обновление средним, но изменим только правило близости. При равных расстояниях будем выбирать первый центр. Для $L_1$ такая договорённость уже нужна: например, V одинаково далека от обоих начальных центров.

*Таблица 4 — Размеры групп по раундам при обновлении средним*

| Как выбираем ближайший центр | Размеры групп от первого раунда до остановки |
| :--- | :--- |
| Квадрат $L_2$ или само $L_2$ | $20/2 \to 15/7 \to 13/9 \to 12/10 \to 12/10$ |
| $L_1$ | $21/1 \to 15/7 \to 12/10 \to 12/10$ |
| $L_\infty$ | $20/2 \to 16/6 \to 13/9 \to 12/10 \to 12/10$ |

Здесь все три запуска **остановились** на тех же группах A–L и M–V и тех же средних центрах $(1{,}83;3{,}33)$ и $(10{,}60;6{,}80)$, но шли к ним по-разному. Это свойство именно наших точек и этого старта. Для $L_1$ и $L_\infty$ пересчёт средним может даже **увеличить сумму выбранных расстояний** при неизменной группе, как показали три точки выше. Поэтому доказательство остановки обычного K-means через уменьшение $J$ к такой замене не относится. Из одного удачного опыта нельзя заключить, что среднее с другим расстоянием всегда приведёт к остановке или к тем же центрам; в программе стоит ограничивать число раундов и проверять повторение групп. Если хотим последовательно уменьшать сумму $L_1$, вместо среднего используем покоординатные медианы. С другими расстояниями правило пересчёта тоже нужно выбирать под измеряемую сумму.

## Типичные ошибки

- При пересчёте центра брать среднее всех точек, а не точек одной группы.
- Считать, что пятый проверочный раунд переместил центры, или что любой остановившийся запуск даёт лучший результат среди всех начальных центров.
- Принимать номера групп за правильные ответы или сравнивать группировки по совпадению этих номеров.
- Полагать, что среднее обязательно минимизирует сумму при любом выборе расстояния.

## Итоги

K-means чередует распределение точек по ближайшим центрам и пересчёт центров как средних по каждой координате. На наших 22 точках два начала дали одинаковые группы, но потребовали пять и два раунда. Сумма квадратов евклидовых расстояний уменьшалась до остановки и показывает компактность, а не «правильный» смысл групп. Другое расстояние может изменить ход алгоритма; правило выбора центра должно соответствовать величине, которую мы хотим уменьшать. Проверьте себя: почему здесь нет обучающих ответов? Что доказывает пятый раунд? Почему для суммы $L_1$ среднее не всегда подходит? Подсказки и решения — ниже.
