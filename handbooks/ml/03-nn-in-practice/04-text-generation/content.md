## Чему научимся

В § 3.3 модель выбирала метку или ближайшую фразу. Теперь попросим небольшую языковую модель **продолжить** начало текста. Вы научитесь различать исходный запрос и сгенерированные токены, менять длину и способ выбора следующего токена, сохранять настройки опыта и проверять фактические утверждения ответа.

После занятия вы сможете:

- Выполнить вручную один шаг выбора следующего токена.
- Сравнить продолжения при неизменных весах и записанных настройках.
- Отделить наблюдение о тексте от проверки фактического утверждения.

**Время и подготовка:** 6–8 часов. Нужны условные вероятности на уровне школьных дробей, Python и представление о токенах из § 2.4. Знание механизма внимания полезно, но для запуска достаточно понимать, что модель получает уже написанную последовательность. Для кода нужны PyTorch и Transformers. Небольшая модель может работать на CPU, но первая загрузка весов требует интернета.

Для запуска скачайте [requirements.txt](../requirements.txt) со страницы главы и установите его в отдельную среду: `python -m pip install -r requirements.txt`. В Colab используйте `%pip install -r requirements.txt` в отдельной ячейке.

Разбиение текста на токены и эмбеддинги можно повторить в [§ 2.4](../../02-dl-basics/04-embeddings/README.md).

## План занятия

1. Выберем вручную следующий токен и разберём настройки выбора.

## Продолжение по одному шагу

Языковая модель получает последовательность **токенов** — частей слов, целых слов или знаков — и выдаёт оценки возможных следующих токенов. Она не пишет всю фразу одним действием. После выбора токен добавляется к входу, и шаг повторяется.

Пусть после «В кружке напечатали» учебная модель предложила три продолжения: «фигурку» с долей 0,60, «задачу» с долей 0,30 и «вчера» с долей 0,10. При **жадном выборе** берём «фигурку». Затем модель снова вычислит оценки, уже для «В кружке напечатали фигурку». Эти учебные доли придуманы для расчёта и не являются выходом реальной модели.

*Рисунок 1 — Генерация как повторение одного шага*

*Таблица 1 — Учебный первый шаг*

| Следующий токен | Доля после softmax |
| :--- | ---: |
| «фигурку» | 0,60 |
| «задачу» | 0,30 |
| «вчера» | 0,10 |

**Сэмплирование** выбирает токен случайно с учётом распределения, поэтому одинаковое начало может дать разные продолжения. Температура меняет относительные доли кандидатов, а `top_k` ограничивает их число. Сначала разберём эти настройки на одном шаге, затем сравним модельные ответы при фиксированных весах и контролируемых условиях.

## Как настройка меняет один шаг

Вернёмся к учебным логитам $(2,1,0)$. При температуре $T=1$ softmax даёт примерно $(0{,}665,\ 0{,}245,\ 0{,}090)$. При $T=2$ перед softmax делим каждый логит на два: получаем $(1,\ 0{,}5,\ 0)$ и доли примерно $(0{,}506,\ 0{,}307,\ 0{,}186)$. Лидер остался прежним, но отрыв уменьшился. При случайном выборе второй и третий токены теперь будут появляться чаще. При жадном выборе результат первого шага не изменится.

Формулу можно проверить без языковой модели. Вычитаем максимум перед экспонентой для устойчивого вычисления; на итоговые доли это не влияет:

```python
import numpy as np

logits = np.array([2.0, 1.0, 0.0])
for temperature in (1.0, 2.0):
    scaled = logits / temperature
    weights = np.exp(scaled - scaled.max())
    probabilities = weights / weights.sum()
    print(temperature, probabilities.round(3))
```

Параметр `top_k` ограничивает множество выбора $k$ ведущими кандидатами. При $k=1$ остаётся только один токен. Температура и `top_k` меняют процедуру выбора, но не знания модели.

## Запустим небольшую модель

Используем готовую русскоязычную модель продолжения текста, а не чат-бота. Её задача — дописывать последовательность. Поэтому короткое начало рассказа подходит лучше, чем сложная инструкция из нескольких пунктов. Пакеты: pip install torch transformers numpy pandas.

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "ai-forever/rugpt3small_based_on_gpt2"
revision = "a9307e696cd3c5b7f953ff4cb19d76a4d81821d5"
tokenizer = AutoTokenizer.from_pretrained(model_id, revision=revision)
model = AutoModelForCausalLM.from_pretrained(model_id, revision=revision).eval()

prompt = "В школьном кружке напечатали фигурку. Она"
encoded = tokenizer(prompt, return_tensors="pt")
with torch.inference_mode():
    output = model.generate(
        **encoded,
        max_new_tokens=40,
        do_sample=False,
        pad_token_id=tokenizer.eos_token_id,
    )
new_ids = output[0, encoded["input_ids"].shape[1]:]
print(tokenizer.decode(new_ids, skip_special_tokens=True))
```

Параметр max_new_tokens ограничивает **добавленные** токены, а не число слов. Срез new_ids удаляет исходный prompt из вывода, чтобы увидеть только продолжение. do_sample=False задаёт жадный выбор. Даже при нём для точного повторения сохраните идентификатор и ревизию весов, версию библиотек, входные токены и настройки; разные среды могут давать отличия.

Остановка по лимиту может оборвать фразу. При разборе отметьте такие обрывы и повторы; один удачный текст не позволяет судить о среднем качестве модели.

Выведем идентификаторы и декодированные части входа. Пробел может входить в токен, а один фрагмент кириллицы иногда кодируется несколькими токенами: при отдельном декодировании части могут выглядеть неполными. Полный текст восстанавливайте из всей последовательности.

```python
ids = encoded["input_ids"][0].tolist()
print([(i, tokenizer.decode([i])) for i in ids])
print("Начало:", tokenizer.decode(ids))
print("Продолжение:", tokenizer.decode(new_ids, skip_special_tokens=True))
```

### Прочитаем реальное продолжение

В проверенном запуске слово «школьном» разделилось на токены с идентификаторами 5993 (` школь`, с начальным пробелом) и 547 (`ном`). Значит, ограничение в 20 новых токенов не равнозначно 20 словам.

Для начала «В школьном кружке напечатали фигурку. Она» жадный выбор с лимитом 20 новых токенов дал продолжение:

```text
 была сделана из бумаги, а на ней был изображен мальчик, который стоял на коленях перед девочкой.
```

Модель дописала материал и сюжет, которых не было во входе. Для художественного продолжения это допустимое развитие, но использовать его как сведения о настоящей фигурке нельзя. При лимите 40 первые токены сохранились и начался диалог. Для начала про самолёт модель упомянула высоту «около 100 метров», затем продолжила переводами строк: больший лимит не гарантирует больше полезного текста. Полные продолжения и параметры сохранены в [записи опытов](../experiment-results.json).

## Сравним условия опыта

В ноутбуке сравните два начала: о фигурке и о модели самолёта. Для каждого модель строит жадное продолжение длиной 20 и 40 новых токенов. Затем для первого начала выполните сэмплирование при $T=0{,}8$ и $T=1{,}2$, используя по три seed для каждой температуры. Так можно сравнить разные начала и длины, а также разброс случайных продолжений при фиксированном prompt. В каждой паре меняйте только один параметр.

```python
torch.manual_seed(7)
with torch.inference_mode():
    sampled = model.generate(
        **encoded,
        max_new_tokens=40,
        do_sample=True,
        top_k=20,
        temperature=0.8,
        pad_token_id=tokenizer.eos_token_id,
    )
print(tokenizer.decode(
    sampled[0, encoded["input_ids"].shape[1]:],
    skip_special_tokens=True,
))
```

Разделяйте наблюдение и объяснение: «в продолжении B появилось слово о крыльях» — наблюдение, «его подсказало слово самолёт» — гипотеза. Сравните таблицу по одному изменённому условию и не делайте вывод о среднем качестве по нескольким примерам.

В таблице ноутбука для каждой строки записаны prompt, лимит новых токенов, режим, seed, температура и продолжение. При повторном запуске с тем же seed можно проверить воспроизводимость в данной среде; это ничего не говорит о достоверности текста.

```python
import pandas as pd

runs = [
    {"prompt": prompt, "max_new_tokens": 40,
     "mode": "greedy", "seed": None,
     "text": tokenizer.decode(new_ids, skip_special_tokens=True)},
    {"prompt": prompt, "max_new_tokens": 40,
     "mode": "sample, top_k=20, T=0.8", "seed": 7,
     "text": tokenizer.decode(
         sampled[0, encoded["input_ids"].shape[1]:],
         skip_special_tokens=True,
     )},
]
report = pd.DataFrame(runs)
print(report[["mode", "max_new_tokens", "seed", "text"]].to_string(index=False))
```

Сначала сравните жадные продолжения при одинаковом лимите и разных началах, затем — длины одного начала. Для сэмплирования сравнивайте одинаковые seed при двух температурах, а внутри каждой температуры — различия между seed. Эти серии показывают, как меняется текст при заданных настройках, но не оценивают качество всех возможных ответов.

### Повторим случайный выбор

Сначала предскажите, при какой температуре продолжения будут разнообразнее. Для одного начала и длины 40 новых токенов запустим две температуры с одинаковым набором seed. Сравнивайте пары с одинаковым seed и отдельно наблюдайте разброс внутри каждой температуры.

```python
for temperature in (0.8, 1.2):
    for seed in (7, 11, 23):
        torch.manual_seed(seed)
        with torch.inference_mode():
            generated = model.generate(
                **encoded, max_new_tokens=40, do_sample=True,
                top_k=20, temperature=temperature,
                pad_token_id=tokenizer.eos_token_id,
            )
        continuation = generated[0, encoded["input_ids"].shape[1]:]
        print(temperature, seed,
              tokenizer.decode(continuation, skip_special_tokens=True))
```

Три seed позволяют увидеть различия, но не измеряют разнообразие всех возможных ответов. Числовой пример выше показывает действие температуры на распределение; связность длинного текста дополнительно зависит от последовательности выбранных токенов.

### Предлагаемая задача для Яндекс Контеста: «Разрешённый следующий токен»

**Условие.** Из логитов возможных токенов выберите разрешённый индекс с наибольшим значением. При равенстве берите меньший индекс. Это один шаг выбора, обучение и загрузка модели не нужны.

**Вход.** В первой строке $n,m$ ($1\le n\le10^5$, $0\le m<n$), затем $n$ целых логитов от $-10^6$ до $10^6$ и $m$ различных запрещённых индексов от 0 до $n-1$.

**Выход.** Один индекс с нуля.

**Пример.** При $n=4$, логитах «3 8 8 1» и запрете индекса 1 ответ: «2».

**Пограничные случаи.** Отрицательные оценки, запрет прежнего лидера, равные логиты. Задачу пока не публикуем.
