## Чему научимся

В § 3.3 модель выбирала метку или ближайшую фразу. Теперь попросим небольшую языковую модель **продолжить** начало текста. Вы научитесь различать исходный запрос и сгенерированные токены, менять длину и способ выбора следующего токена, сохранять настройки опыта и проверять фактические утверждения ответа.

После занятия вы сможете:

- Выполнить вручную один шаг выбора следующего токена.
- Сравнить продолжения при неизменных весах и записанных настройках.
- Отделить наблюдение о тексте от проверки фактического утверждения.

**Время и подготовка:** 6–8 часов. Нужны условные вероятности на уровне школьных дробей, Python и представление о токенах из § 2.4. Знание механизма внимания полезно, но для запуска достаточно понимать, что модель получает уже написанную последовательность. Для кода нужны PyTorch и Transformers. Небольшая модель может работать на CPU, но первая загрузка весов требует интернета.

## План занятия

1. Выберем вручную следующий токен и разберём настройки выбора.
2. Запустим русскоязычную модель и сравним два начала текста.
3. Проверим факты и запишем условия воспроизводимого опыта.

## Продолжение по одному шагу

Языковая модель получает последовательность **токенов** — частей слов, целых слов или знаков — и выдаёт оценки возможных следующих токенов. Она не пишет всю фразу одним действием. После выбора токен добавляется к входу, и шаг повторяется.

Пусть после «В кружке напечатали» учебная модель предложила три продолжения: «фигурку» с долей 0,60, «задачу» с долей 0,30 и «вчера» с долей 0,10. При **жадном выборе** берём «фигурку». Затем модель снова вычислит оценки, уже для «В кружке напечатали фигурку». Эти учебные доли придуманы для расчёта и не являются выходом реальной модели.

| Следующий токен | Доля после softmax |
| :--- | ---: |
| «фигурку» | 0,60 |
| «задачу» | 0,30 |
| «вчера» | 0,10 |

**Сэмплирование** вместо выбора максимума случайно берёт токен согласно распределению. Тогда при одинаковом начале возможны разные продолжения. Настройки temperature и top-k меняют выбор: temperature изменяет резкость распределения, top-k оставляет только несколько ведущих кандидатов. Не будем искать «волшебное» значение; сначала сравним одинаковые запросы при одинаковых весах.

## Как настройка меняет один шаг

Вернёмся к учебным логитам $(2,1,0)$. При температуре $T=1$ softmax даёт примерно $(0{,}665,\ 0{,}245,\ 0{,}090)$. При $T=2$ перед softmax делим каждый логит на два: получаем $(1,\ 0{,}5,\ 0)$ и доли примерно $(0{,}506,\ 0{,}307,\ 0{,}186)$. Лидер остался прежним, но отрыв уменьшился. При случайном выборе второй и третий токены теперь будут появляться чаще. При жадном выборе результат первого шага не изменится.

Формулу можно проверить без языковой модели. Вычитаем максимум перед экспонентой для устойчивого вычисления; на итоговые доли это не влияет:

```python
import numpy as np

logits = np.array([2.0, 1.0, 0.0])
for temperature in (1.0, 2.0):
    scaled = logits / temperature
    weights = np.exp(scaled - scaled.max())
    probabilities = weights / weights.sum()
    print(temperature, probabilities.round(3))
```

Параметр top-k действует иначе: он ограничивает множество доступных кандидатов до $k$ ведущих, затем случайный выбор проводится среди них. Если $k=1$, случайности на этом шаге не остаётся. Эти настройки меняют **выбор токена**, но сами по себе не учат модель новым фактам и не делают ответ достоверным.

## Запустим небольшую модель

Используем готовую русскоязычную модель продолжения текста, а не чат-бота. Её задача — дописывать последовательность. Поэтому короткое начало рассказа подходит лучше, чем сложная инструкция из нескольких пунктов. Пакеты: pip install torch transformers numpy pandas.

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "ai-forever/rugpt3small_based_on_gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).eval()

prompt = "В школьном кружке напечатали фигурку. Она"
encoded = tokenizer(prompt, return_tensors="pt")
with torch.inference_mode():
    output = model.generate(
        **encoded,
        max_new_tokens=40,
        do_sample=False,
        pad_token_id=tokenizer.eos_token_id,
    )
new_ids = output[0, encoded["input_ids"].shape[1]:]
print(tokenizer.decode(new_ids, skip_special_tokens=True))
```

Параметр max_new_tokens ограничивает **добавленные** токены, а не число слов. Срез new_ids удаляет исходный prompt из вывода, чтобы увидеть только продолжение. do_sample=False задаёт жадный выбор. Даже при нём для точного повторения сохраните идентификатор и ревизию весов, версию библиотек, входные токены и настройки; разные среды могут давать отличия.

Результат не обязательно будет грамматически законченным: остановка по числу токенов может оборвать фразу. Если продолжение бессмысленно, сначала проверьте исходное начало, язык и ограничения модели. Не называйте один удачный текст доказательством понимания.

## Сравним условия опыта

Сделайте два начала об одной теме:

- A: «В школьном кружке напечатали фигурку. Она»
- B: «В школьном кружке напечатали модель самолёта. Она»

Для каждого запустите 20 и 40 новых токенов. Сохраните четыре продолжения. Изменяйте за раз только начало **или** ограничение длины: тогда видно, с чем связано различие. Затем при одном неизменном начале попробуйте сэмплирование с do_sample=True и фиксированным torch.manual_seed(7). Повторите запуск; при одинаковой среде результат обычно совпадёт, но это не замена записи версии весов и библиотек.

```python
torch.manual_seed(7)
with torch.inference_mode():
    sampled = model.generate(
        **encoded,
        max_new_tokens=40,
        do_sample=True,
        top_k=20,
        temperature=0.8,
        pad_token_id=tokenizer.eos_token_id,
    )
print(tokenizer.decode(
    sampled[0, encoded["input_ids"].shape[1]:],
    skip_special_tokens=True,
))
```

В отчёте разделите наблюдение и объяснение. Например, «при B появилось слово о крыльях» — наблюдение; «вероятно, его подсказало слово самолёт» — гипотеза. Не делайте вывод о среднем качестве по четырём продолжениям.

Для сравнения режимов удобно сохранить условия в таблице, как мы делали с ошибками моделей в главе 1. Строка опыта должна содержать неизменный prompt, число новых токенов, режим выбора, seed (если он нужен), сам ответ и замечание о фактах. Для двух запусков с одним seed не считайте совпадение доказательством качества: это лишь повторяемость вычисления при данных настройках.

```python
import pandas as pd

runs = [
    {"prompt": prompt, "max_new_tokens": 40,
     "mode": "greedy", "seed": None,
     "text": tokenizer.decode(new_ids, skip_special_tokens=True)},
    {"prompt": prompt, "max_new_tokens": 40,
     "mode": "sample, top_k=20, T=0.8", "seed": 7,
     "text": tokenizer.decode(
         sampled[0, encoded["input_ids"].shape[1]:],
         skip_special_tokens=True,
     )},
]
report = pd.DataFrame(runs)
print(report[["mode", "max_new_tokens", "seed", "text"]].to_string(index=False))
```

Сравнение разных начал текста делайте отдельной парой строк. Иначе невозможно понять, связано ли изменение ответа с началом, случайностью или длиной. В большой серии ответов понадобились бы ясные критерии оценки; два продолжения полезны только для первого знакомства с механизмом.

## Проверка фактов и границы применения

Продолжение может содержать дату, имя или число, которые выглядят убедительно и при этом выдуманы. Выберите одно проверяемое утверждение из выхода. Найдите надёжный внешний источник и запишите, подтвердилось ли оно. Если проверить нельзя, так и напишите. Истинность предложения не следует из его плавного стиля или высокой оценки модели.

Модель продолжения текста может воспроизводить стереотипы или неподходящие фразы из обучающих данных. Для учебного опыта не вводите личные данные и не публикуйте вывод без чтения. На белорусском языке маленькая русскоязычная модель может работать хуже; проверьте это отдельно на безопасных коротких началах и не заявляйте поддержку языка по одному примеру.

## Практика

1. Вручную объясните первый шаг учебного распределения 0,60/0,30/0,10 при жадном выборе и при случайном сэмплировании. В обоих случаях следующий шаг получает уже расширенный текст.
2. Проведите опыт A/B выше. Составьте таблицу «начало — число новых токенов — режим выбора — фрагмент ответа — что проверили». Сравните только пары, где изменён один параметр.
3. Найдите в выводе фактическое утверждение. Проверьте его отдельно и сохраните ссылку на источник либо отметку «не удалось проверить». Не исправляйте исходный вывод задним числом.

### Предлагаемая задача для Яндекс Контеста: «Разрешённый следующий токен»

**Условие.** Из логитов возможных токенов выберите разрешённый индекс с наибольшим значением. При равенстве берите меньший индекс. Это один шаг выбора, обучение и загрузка модели не нужны.

**Вход.** В первой строке $n,m$ ($1\le n\le10^5$, $0\le m<n$), затем $n$ целых логитов от $-10^6$ до $10^6$ и $m$ различных запрещённых индексов от 0 до $n-1$.

**Выход.** Один индекс с нуля.

**Пример.** При $n=4$, логитах «3 8 8 1» и запрете индекса 1 ответ: «2».

**Пограничные случаи.** Отрицательные оценки, запрет прежнего лидера, равные логиты. Задачу пока не публикуем.

Генератор повторяет шаг «оценить следующий токен — выбрать — добавить». Мы сохранили настройки, сравнили продолжения и отделили красивый текст от проверенного факта. В последнем параграфе используем модель, которая связывает текст с изображением без генерации ответа.
